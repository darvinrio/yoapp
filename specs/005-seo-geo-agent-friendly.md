# SEO, GEO & Agent-Friendly Metadata

Make the site fully machine-readable for search engines and AI agents: shared head component with OG/Twitter/canonical tags, sitemap, robots.txt, llms.txt, RSS, JSON-LD structured data, a complete favicon set, a template-driven OG image generator, self-hosted fonts, inline SVG icons, and a styled 404. Everything is build-time only — zero Vercel functions — so it fits the Vercel free tier.

## Decisions (locked during interview)

| Decision        | Value                                                                                                          |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| Canonical URL   | `https://mayonas.vercel.app` (single source: `site` in `astro.config.mjs`)                                     |
| Site brand      | `maybeYonas` (title suffix)                                                                                    |
| Person name     | `Yonas`                                                                                                        |
| Job title       | `Analytics Engineer` (adopted in all metadata text: home title, descriptions, JSON-LD, llms.txt, OG image)     |
| OG image        | One site-wide `public/og.png`, generated by a satori + resvg script; stable URL so social caches never break   |
| AI crawlers     | Fully allowed (robots.txt: `User-agent: * / Allow: /`)                                                         |
| llms.txt        | Build-generated from the content collection; index only (no llms-full.txt, no per-post .md)                    |
| Asset placement | System-wide assets (favicons, fonts, site-wide `og.png`) → `public/`; per-page/per-post assets → `src/assets/` |

## Scope

- New packages: `@astrojs/sitemap`, `@astrojs/rss`, `satori`, `@resvg/resvg-js` (all build-time/dev-time)
- One config touched: `astro.config.mjs`

## 1. Astro Config

**File:** `astro.config.mjs`

```js
import sitemap from "@astrojs/sitemap";

export default defineConfig({
  site: "https://mayonas.vercel.app",
  integrations: [mdx(), sitemap()],
  // markdown / vite blocks unchanged
});
```

- `site` is the single source of truth. Sitemap, canonical URLs, OG URLs, llms.txt links, and RSS item links all derive from `Astro.site` / `new URL(path, Astro.site)` — never hardcoded elsewhere.
- RSS is not an integration; it is a page endpoint (see §8).

## 2. BaseHead Component

**Path:** `src/components/BaseHead.astro`

Single owner of the entire `<head>`. Both layouts render exactly one `<BaseHead {...props} />` and keep no head markup of their own.

### Props

```ts
interface Props {
  title?: string; // page-specific title; undefined → home default
  description?: string; // meta description
  image?: string; // path relative to site root; default "/og.png"
  type?: "website" | "article"; // default "website"
  publishedTime?: Date; // required when type === "article"
  structuredData?: object[]; // JSON-LD nodes, rendered one <script> per node
}
```

### Title logic

- Home (no `title` prop): `maybeYonas — Analytics Engineer`
- Otherwise: `` `${title} · maybeYonas` ``

### Description defaults

| Page       | Default description                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| Home       | `Analytics Engineer with 4 years of blockchain data experience. On-chain data, prediction markets, open research.` |
| Blog index | `Writings on on-chain data, DeFi analytics, and prediction markets by maybeYonas.`                                 |
| Post       | `post.data.description` (already in frontmatter — required field, no schema change)                                |
| Resume     | `Resume of Yonas (maybeYonas) — Analytics Engineer with 4 years of blockchain data experience.`                    |
| Work       | `Work experience of Yonas (maybeYonas) — analytics and data engineering roles across DeFi.`                        |

### Tags rendered (in order)

1. `<meta charset>`, `<meta viewport>`, `<meta name="generator">`
2. `<title>`
3. `<meta name="description">`
4. `<link rel="canonical">` — `new URL(Astro.url.pathname, Astro.site)`
5. Open Graph: `og:title`, `og:description`, `og:type` (`website`/`article`), `og:url` (absolute, same as canonical), `og:image` (absolute URL, default `https://mayonas.vercel.app/og.png`), `og:site_name` (`maybeYonas`), and `article:published_time` when `type === "article"`
6. Twitter: `twitter:card` = `summary_large_image`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:site` = `@maybeYonas`
7. Icons + manifest (§5), `theme-color` (§5), font preloads (§6)
8. One `<script type="application/ld+json" set:html={JSON.stringify(node)} />` per `structuredData` entry (`set:html` avoids HTML-entity escaping inside the script)

The component reads `Astro.site` and `Astro.url` itself; callers never build absolute URLs.

## 3. Layouts & Pages

## 5. OG Image Generator (satori + resvg)

**Path:** `scripts/generate-og.ts`, run manually via `bun scripts/generate-og.ts` whenever template text changes. Output committed: `public/og.png` (1200×630, stable URL — site-wide "system-wide" asset per the placement rule; hashed `/_astro/` URLs would invalidate old social link previews).

### Dependencies

```sh
bun add satori @resvg/resvg-js
```

### Fonts (build inputs, not browser assets)

Satori requires TTF/OTF buffers (woff2 unsupported). Vendor exactly two files into `scripts/fonts/`:

- `Merriweather-Bold.ttf` (headline)
- `JetBrainsMono-Regular.ttf` (footer tagline)

They are script-local tooling, distinct from the self-hosted woff2 files in `public/fonts/` (§6).

### Template

All copy lives in named constants at the top of the script — editing text = editing constants + rerunning:

```ts
const WORDMARK = "maybeYonas.";
const HEADLINE_LINE_1 = "Analytics Engineer,";
const HEADLINE_LINE_2 = "reconciling data to the last share.";
const FOOTER = "on-chain data · prediction markets · open research";
```

### Colors (theme-mapped)

| Element                     | Color                          |
| --------------------------- | ------------------------------ |
| Background                  | `#18181b`                      |
| Top accent bar (full-width) | `#2dd4bf`                      |
| Flag glyph + wordmark dot   | `#2dd4bf` flag, `#f1eef7` text |
| Headline line 1             | `#f1eef7`                      |
| Headline line 2             | `#a1a1aa`                      |
| Divider                     | `#3f3f46`                      |
| Footer tagline (mono)       | `#a1a1aa`                      |

### Layout (matches the reference design)

1. Full-width 8px accent bar at the very top (`#2dd4bf`).
2. Flag glyph: vertical rounded bar + triangular pennant pointing right, teal — recreated as satori-compatible divs/SVG, echoing `favicon.svg`.
3. `maybeYonas.` wordmark, Merriweather Bold, white.
4. Two-line headline, Merriweather Bold ~64px: line 1 white, line 2 gray.
5. Thin divider `#3f3f46` above the footer.
6. Footer tagline in JetBrains Mono ~24px with `·` separators.

Pipeline: satori renders the JSX element tree → SVG string → `@resvg/resvg-js` `Resvg` → PNG buffer → write `public/og.png`. No network requests; fonts read from `scripts/fonts/`.

Download the latin-subset woff2 files into `public/fonts/` (system-wide assets):

- JetBrains Mono: 400, 500, 700

```html

  type="font/woff2"

```

Exact filenames are the Google Fonts latin-subset names as downloaded; keep them consistent between `public/fonts/`, `global.css`, and the preloads.

## 10. llms.txt (build-generated)

**Path:** `src/pages/llms.txt.ts` — prerendered endpoint returning `text/plain; charset=utf-8`, generated from the content collection so it can never go stale.

Shape (llms.txt convention):

```
# maybeYonas

> Analytics Engineer with 4 years of blockchain data experience. On-chain data, prediction markets, open research.

Analytics engineering, DeFi analytics research, and prediction-market forensics by Yonas (maybeYonas).

## Pages

- [Home](https://mayonas.vercel.app/): Analytics Engineer — on-chain data, prediction markets, open research
- [Writings](https://mayonas.vercel.app/blog): All published posts
- [Work](https://mayonas.vercel.app/work): Work experience
- [Resume](https://mayonas.vercel.app/resume): Resume
- [RSS](https://mayonas.vercel.app/rss.xml): Feed of new posts

## Writings

- [Polymarket Ledger](https://mayonas.vercel.app/blog/polymarket-ledger): 2025-12-20 — <frontmatter description>
- [...one entry per post, newest first...]
```

Rules:

- Every URL absolute via `new URL(path, Astro.site)`.
- Post line format: `- [Title](url): YYYY-MM-DD — description`.
- Built with `getCollection("blog")` sorted by `date` descending.
- No `llms-full.txt`, no per-post `.md` endpoints (non-goals).

## 11. RSS Feed

**Path:** `src/pages/rss.xml.ts` using `@astrojs/rss`:

```ts
export async function GET(context) {
  const posts = (await getCollection("blog")).sort(
    (a, b) => b.data.date.valueOf() - a.data.date.valueOf(),
  );
  return rss({
    title: "maybeYonas",
    description: "On-chain data, prediction markets, open research.",
    site: context.site,
    items: posts.map((post) => ({
      title: post.data.title,
      description: post.data.description,
      link: `/blog/${post.id}/`,
      pubDate: post.data.date,
    })),
  });
}
```

Output: `/rss.xml`, listed in robots-reachable llms.txt (§10). No XSL stylesheet (non-goal).
